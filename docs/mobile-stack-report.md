# 移动端堆叠卡片优化报告 —— 首页活动区 + 「带上她的眼睛」项目主页

> 调研日期:2026-10-16 · 范围:首页 `#activities`(ActsSection 拍立得照片堆)与
> `/welfare/`(图文手记堆叠卡片),390×844 移动端视口实测取证。

## 一、现状与问题(实拍取证)

取证截图:`docs/img/mobile-stack-before-home.png`、`mobile-stack-before-welfare.png`(390×844 实拍)。

两页共用同一套「拍立得堆叠」语言:卡片带 ±2~4° 旋转与 ±10px 上下偏移,`mouseenter`/
`focus`
时该卡弹出(转正、上提、放大、投影加深);卡片标题以绝对定位贴在白框底部 (`.stack-meta`,距卡底 17px)。**这套语言在移动端失效,有两个确定性问题:**

1. **堆叠遮挡标题**:移动端以 -30~-34px 负 margin 垂直堆叠,每张卡的顶边正好压住上一张卡的白框标题区。实测:首页「时间的故事」标题被第二张卡整张盖住;公益主页《在遥远的地方》同样。只有初始渲染时写死
   `.active` 的那张卡能看到标题。
2. **弹出交互不可感知**:触发弹出的 `mouseenter` 在触屏上不存在、`focus`
   只在键盘导航时出现——移动端用户既感受不到交互,又面对一张"莫名其妙地"弹着的卡(渲染时写死
   `index === 1`),且弹出卡的标题因单行 nowrap 被截断("Seeker公益 · 带上她的…")。

## 二、方案对比

| 方案                | 思路                                                  | 优点                           | 缺点                                                          | 结论        |
| ------------------- | ----------------------------------------------------- | ------------------------------ | ------------------------------------------------------------- | ----------- |
| A. 平铺卡片流       | 取消重叠改纵向列表                                    | 标题最可靠;改动小              | 丢失堆叠隐喻(用户认可的设计)                                  | 备选        |
| **B. 微重叠(采纳)** | 保留堆叠,重叠量收敛到只压白框下缘+阴影,标题区完整露出 | 保留堆叠隐喻;桌面零改动;纯 CSS | 重叠量需给旋转角下探留安全边距(已计算,见下)                   | ✅ 用户选定 |
| C. 横滑卡组         | scroll-snap 横向轮播+露边                             | 保留"还有更多"暗示             | 首页整屏 snap 内嵌套横滑体验微妙;改动最大;手记仅 3 篇轮播过重 | 否          |

两段式点击(先弹出再跳转)在方案设计阶段即被否决:违反移动端"点链接即跳转"的默认心智,增加一次无意义点击。

## 三、落地设计(方案 B)

全部改动收在 `@media (max-width: 768px)`,**桌面端(>768px)逐字节不变**——
hover 弹出交互原样保留。两个组件同一配方:

```css
.stack-card {
  padding-bottom: 64px; /* 56→64:标题区加高,容下纵向双行标题 */
  transform: rotate(
    calc(var(--rot) * 0.25)
  ); /* 旋转降为 1/4(≤1°),并抵消 ±10px 的 --dy 偏移 */
}
.stack-card + .stack-card {
  margin-top: -12px;
} /* 微重叠:只压白框下缘 + 阴影 */
.stack-card.active {
  transform: rotate(
    calc(var(--rot) * 0.25)
  ); /* 移动端取消弹出位移(触屏不可感知且会压住上一张标题) */
  box-shadow: var(--paper-shadow-lift); /* 保留抬升阴影作为"当前卡"暗示 */
}
.stack-meta {
  bottom: 18px; /* 标题文字距卡底 ≥18px */
  flex-direction: column; /* 标题/副题纵向两行,去掉单行截断 */
  align-items: flex-start;
  gap: 2px;
}
.stack-meta strong {
  white-space: normal;
} /* 标题可换行(现网标题均单行放得下) */
```

**二次微调(同日,用户反馈)**:卡片增加 `±14px` 左右交替错位(`--sx` 变量 +
nth-child
odd/even),与微重叠叠加后形成竖向瀑布式垂落,强化「一条线下来」的卡片组叙事;错位经 translateX 实现,标题安全边距计算不受影响。

**几何安全验证**(最坏情形 = 最宽卡 380px、旋转 1°):

- 覆盖卡顶边下探 = 重叠 12px + 旋转角下探 (W/2)·sin(1°) ≈ 2.6px = **14.6px**
- 标题文字距卡底 18px → **安全边距 ≥ 3.4px**,即标题永远不会被下一张卡触碰
- 被覆盖的 12px 全部落在白框下缘空白 + 阴影区,照片本体不受影响
- 旋转/偏移是内联 style(每卡随机),无法单独覆盖,故用整条 `transform` 覆盖的
  `calc(var(--rot) * 0.25)` 写法,同时抵消 `--dy`

**附加修复**:`/welfare/`
的 hero 导语存在与《时间的故事》此前已修复的同款拥挤问题 (14.5px +
`text-align: justify`),本分支按同一已确认配方顺带修复(justify→center、15.5px、行高 2.1)。
